# JSON Schema

> The config schema published as a standard JSON Schema document — where it comes from, how to generate it, and which URL to point a pipeline at.

The app schema describes the complete structure of an application configuration. It is published as **JSON Schema Draft 2020-12**, derived directly from the canonical schema the server decodes with, so it cannot drift from what the binary actually accepts.

Three artefacts come off that one source of truth, and choosing between them is a question of when you want to be told.

| Artefact           | Format              | Generated by       | Use it for                            |
| ------------------ | ------------------- | ------------------ | ------------------------------------- |
| JSON Schema        | JSON, Draft 2020-12 | `sovrium schema`   | Editor autocomplete, CI validation    |
| A type declaration | TypeScript `.d.ts`  | `sovrium types`    | Autocompletion in a TypeScript config |
| The decoder itself | A runtime decode    | `sovrium validate` | Checking a config before deploying it |

The first two answer while you type; the third answers about the config as a whole, including the cross-section rules neither of the others can see.

## Generating it

```bash
sovrium schema
sovrium schema --output app.schema.json
```

With no output path the document goes to stdout. It is self-contained, carrying a top-level `$schema` declaration, so any JSON-Schema-aware tool consumes it without further configuration.

It takes no input beyond the binary itself — no config file, no environment — so **regenerating it in CI and diffing the result makes any change a real schema change**. That is the cheap way to notice that an upgrade moved the contract under you.

## The root properties

Every property except the app's `name` is optional and layers on top of what is already there. The full reference, one row per root property with its type and description, is the schema-overview article; this page is about the published document rather than its contents.

## Which URL to reference

### Pinned to a version

```text
https://sovrium.com/schema/app-<version>.json
```

Replace the placeholder with the version `sovrium --version` prints. **A pinned URL is the one that keeps CI honest**: the config is checked against the schema of the version you actually deploy, so upgrading the binary and adopting its new schema stay two separate decisions rather than one silent one.

### Latest

```text
https://sovrium.com/schema/app.json
```

Always the most recent version. Convenient in development, and able to introduce a breaking change without warning — which is the same property read twice, depending on whether a human or a pipeline is reading it.
